# v1.8.3 一次实机验证窗口

本流程由用户手动执行，不安装服务或新增CatWrt依赖。已有Lua/curl、原生锁、状态文件、停止监督单项和控制器文件校验不重复。使用现有私有备份；先准备SSH窗口和以下命令，再统一更换模块并重启一次。范围核对工具只读文件，不访问API、不测速、不写配置；它只需要目标已具备的Ruby YAML库。

公开良心云显示自动，控制器持续管理四档；TikTok保留手选iKuuu日本首跳与Loongproxy美国出口；直连采用仓库源的全部规则。当前源148条是快照，不是数量限制。未触发的故障降级／恢复不能记为实机通过，CI相关用例与实机记录分开。

## 3. 只读核对后启动一次持续测试

范围核对：`ruby liangxinyun_v183_runtime_scope.rb 当前运行YAML 完整云缓存 增量缓存 < before-v183.yaml`。

成功应passed、directMatchesCloud、outsideLiangxinyunUnchanged均true。它允许基线141条升级为仓库授权的148条，保留源的内容、顺序及重复项；仅为文件快照，不声称核心内存已验证。失败则回退本次增量，回贴脱敏JSON，不继续试错。

随后执行控制器--preflight，仅candidateCompatible:true才继续。通过原监督脚本执行--run，复用同一个临时锁，记录状态和控制日志，保持SSH窗口打开。无需先重复--once；持续模式的首个成功周期已执行相同的初始化、检测、选择和读回。

监督脚本会使用 `/tmp/liangxinyun-stop.<监督PID>`。启动者记录监督PID，并wait等待其退出；从第二个SSH窗口创建对应停止标记，触发合作式清理。不要依赖关闭SSH窗口来停止测试。正常结束应reason=supervisor-stop、verifiedSelection:true、wouldSelect=REJECT，监督退出码0。

## 4. 业务与观察（建议5–10分钟）

- 面板良心云类型显示自动，TikTok两个组继续手动；内部组的隐藏效果和当前叶节点可查看性记录实际结果，不要求更新面板。
- 首个成功周期有verifiedSelection:true、合法LXY叶节点及档位。日本专线有健康节点时应留在该档，档内选最低新鲜延迟；不要手选良心云。稳定时日志未连续刷屏属于正常，仅变化才打印，状态文件仍持续更新。
- 手机打开并播放TikTok，记下实际iKuuu日本首跳；普通代理测试YouTube、Telegram及平时使用的站点。
- 访问一个大陆站点和一个平时可用的手动直连站点，结合日志确认规则；大陆旁路可能不出现在核心连接列表。
- 只记录真实发生的节点失效／降级／恢复。没有发生的全档故障不能伪造通过，也不临时改节点地址、凭据、订阅或防火墙制造故障。

测试期间通过运行日志→调试日志→生成日志保存本候选证据。分享前遮盖真实订阅、密码及面板密钥；完整运行配置和基线只留本地。

## 5. 停止、回退与回传

第二SSH窗口写入停止标记后，第一窗口应正常结束并输出监督退出码0。停止后普通代理会在REJECT，立即在覆写模块关闭v1.8.3、恢复v1.8.2增量并重启；原完整云继续使用仓库全部规则，不退回141条。手选原良心云可用节点（例如此前日本专线02）以恢复普通代理，TikTok日本首跳保持；复测普通代理、TikTok和直连。

这次没有安装服务，无需执行服务安装、启用或禁用。若计划继续保留候选运行，应保持监督会话，而不能将一次选择当作持续自动。

集中回传：范围检查JSON、preflight与首个成功周期、面板实际显示、TikTok首跳及播放、普通代理/直连、停止与回退结果、脱敏调试日志。未完成的项写“未验证”。正式发布沿用已授权流程，达到验收条件后直接发布并同步，不重复询问许可。
