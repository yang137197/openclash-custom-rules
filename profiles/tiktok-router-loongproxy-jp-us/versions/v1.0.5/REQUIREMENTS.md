# tiktok-router-loongproxy-jp-us v1.0.5 — 正式需求合同

状态：**stable**。用户于 2026-10-24 明确授权正式发布。本版本只修正本地节点模板的下载文件扩展名，不改变云覆写规则、代理链路或 OpenClash 插件设置。云覆写内容与已验收的 v1.0.4 完全一致；v1.0.4 发布目录、标签和 Release 保持不变。路由器本地文件选择器本次未实测，不将其记作已验收。

本方案的 J1–J11 首次定义于 v1.0.0。本版本继承 v1.0.4 的 J1–J11、J13、J14、J15 及 iKuuu 日本首跳前提。Loongproxy 链路必须通过用户手选的 iKuuu 日本节点作为第一跳；不得换用美国首跳，也不得在链路失效时回退机场或 `DIRECT`。TikTok/Claude ISP 出口、GitHub/Google 分流、中国大陆直连、129 条 Manual-Direct 和失败关闭行为均不变。

## 需求

- J13：沿用 v1.0.4 Claude Code 官方端点规则，仍走 `TikTok-ISP`。
- J14：沿用 v1.0.4 Claude/Anthropic 第一方域名规则，仍走 `TikTok-ISP`。
- J15：沿用 v1.0.4 GitHub 域名规则，仍走 `美国`。
- J16：本地 SOCKS5 模块下载模板必须使用 OpenClash 本地模块上传器支持的 `.conf` 文件扩展名；不得将可直接导入的 Release 附件命名为 `.example` 或 `.conf.example`。模板正文继续使用 OpenClash 模块段头 `[YAML]`，且仅含占位凭据。用户替换占位值后，应能直接通过「本地模块」文件选择器导入，无需先重命名文件。节点名、SOCKS5 类型、`udp: false` 与 `dialer-proxy: 日本-入口` 保持不变。

## 验收条件

1. **静态验证通过**：模板最终扩展名为 `.conf`，正文含 `[YAML]` 段头，可由仓库模块解析器读取，并与 v1.0.4 占位模板逐字节一致。
2. **官方格式依据已确认，路由器操作未实测**：官方指南列出本地上传支持 `.txt`、`.conf`；未在目标路由器文件选择器实际选择/读取该文件，不声称通过该实机步骤。
3. 云覆写与 v1.0.4 完全相同；本版本不要求切换运行中的云覆写，不代表新的路由行为实机验收。
4. 真实 ISP 地址、用户名和密码不得提交到仓库或公开 Release。

## 版本边界

v1.0.4 Release 附件使用 `.conf.example`，不符合 OpenClash 本地模块上传器列出的 `.txt`/`.conf` 文件类型。该已发布快照不可改写；下载 v1.0.4 附件的临时处理方式是先将文件名改为 `.conf`。v1.0.5 提供最终扩展名为 `.conf` 的附件。本次正式发布由用户明确授权；文件选择器实测仍未完成。
