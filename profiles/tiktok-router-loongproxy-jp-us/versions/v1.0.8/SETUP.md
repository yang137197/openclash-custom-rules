# tiktok-router-loongproxy-jp-us v1.0.8 候选应用与回退

这是 **candidate**，尚未在用户 CatWrt 上验收。仅使用两个 `[YAML]` 覆写模块；没有控制器、服务、opkg安装或额外依赖。由用户手动操作路由器。

## 先保存可恢复基线

在改变模块前，保存当前可用的完整云模块和本地节点模块的内容、远程URL、启用状态、当前配置完整路径及模块排序截图。私有副本仅存自己电脑，不发送到聊天或GitHub。通过 OpenClash 运行状态页顶部“覆写模块”打开编辑器；官方行为见16-overwrite-module-format.md §16.1.1。

备份必须能恢复一整套可用的配对模块。没有原可用本地 ISP 参数或完整回退副本时，不开始应用；不提供未经核验的通用 tar 恢复命令。

## 准备本地模块

下载同一候选提交中的 `local-tiktok-proxy.conf`，只在私有副本填写：

| 占位项 | 填入内容 |
|---|---|
| FILL_ME_IKUUU_SUBSCRIPTION_URL | iKuuu 的 Mihomo/Clash YAML 节点订阅；不要用Base64 URI订阅 |
| FILL_ME_LIANGXINYUN_SUBSCRIPTION_URL | 良心云的 Mihomo/Clash YAML 节点订阅 |
| FILL_ME_PROXY_HOST | 现有 Loongproxy 美国出口主机 |
| FILL_ME_PROXY_PORT | 现有端口，填写整数 |
| FILL_ME_USERNAME / FILL_ME_PASSWORD | 现有账号和密码，保留正确 YAML 引号 |

订阅凭据包含特殊字符时用 YAML 单引号包住完整URL，内部单引号写成两个单引号。不要改变 `TikTok-ISP-Local`、socks5、udp:false、`dialer-proxy: TikTok首跳`。订阅使用原生 proxy-providers，更新间隔3600秒；下载策略为 DIRECT，需实测路由器能直接拉取两条订阅。本地模板不自动调用订阅转换服务。

新方案仅使用这两个命名提供商的节点；底层原机场配置即使还有其他节点也不会混入四个组。两个iKuuu组共享同一提供商。提供商自动添加 IK:/LXY: 名称前缀，不用人工改原订阅。

## 手动应用

1. 在运行状态页顶部“覆写模块”添加本地模块，上传填好的 `.conf`，名称建议 `dual-jp-local`；完整云覆写通过远程订阅模块添加，名称建议 `dual-jp-cloud`，URL必须是交付的同一固定候选提交。不要直接使用正式入口或不固定的分支地址。
2. 两个新模块匹配同一个当前配置的完整路径（如 `/etc/openclash/config/实际配置名.yaml`）。云模块放在本地模块上方，列表越靠上越晚合并；两个模块初始保持停用，先检查内容和排序。
3. 关闭旧的一套完整云模块及旧ISP本地模块、所有历史测试模块；启用本次两个配对模块。不要在“没有任何完整方案”的中间状态测试访问；全部调整完成后统一重启 OpenClash。
4. 检查四个显式组及节点归属，`Tiktok美国出口测速`只能有 `TikTok-ISP-Local`。原“日本-入口”“TikTok-ISP”“美国”不得作为新方案引用残留。GLOBAL由内核生成，无定时检测。
5. 先测普通代理与DIRECT，再验证TikTok播放，随后验证良心云分流和故障/恢复。节点缺失、启动解析失败、普通代理或TikTok断连即停止验证，执行下方完整回退，不连续更换开关试错。

## OpenClash 设置建议

本模块不写 UCI。已有设置保持实际基线；下表供新安装或恢复默认后核对，不要求为候选随意改变现有开关。路径均在“服务→OpenClash”下，来源为官方指南08/09/10/11对应设置章节及原正式版设置基线；本候选的实际设置是否一致仍待日志。

| 页面 | 设置 | 建议与适用条件 |
|---|---|---|
| 插件设置→模式设置 | 运行模式/代理模式 | 原基线 Fake-IP增强、规则模式；不借本候选改TUN/混合模式 |
| 同上 | UDP转发 | 沿用现状；ISP节点udp:false保持 |
| 同上 | 旁路网关兼容 | 主路由/回程正常建议关闭，仅依据回程证据调整 |
| 插件设置→流量控制 | 路由器本机代理 | 原正式版建议开启；订阅的显式DIRECT下载需独立验证 |
| 同上 | 绕过指定区域IPv4 | 原基线绕过中国大陆，数据源MetaCubeX cn.mrs；候选不改 |
| 同上 | 禁用QUIC | 原正式版建议开启，但实际值以当前设备记录为准；候选不改 |
| 同上 | 绕过服务器地址/仅允许内网访问 | 建议开启，沿用基线 |
| 同上 | 仅允许常用端口 | 建议关闭，沿用基线 |
| 插件设置→IPv6设置 | IPv6代理/DNS/区域绕过 | 原基线关闭；不宣称全网IPv6已关闭 |
| 插件设置→DNS设置 | 本地DNS劫持 | 原基线Dnsmasq转发；客户端需使用路由器DNS |
| 覆写设置→DNS设置 | 自定义上游DNS/遵守路由规则/Fake-IP持久化 | 原基线开启，候选沿用解析器结构 |
| 同上 | 附加上游/追加默认DNS/Fallback | 原基线关闭，由完整云模块管理 |
| 同上 | 自定义Fake-IP-Filter | 原基线开启、rule模式，保留TikTok/Google优先Fake-IP |
| 覆写设置→Meta设置 | 嗅探/纯IP嗅探/进程查找 | 原基线前两项开启、进程查找off；不改变 |
| 覆写设置→规则设置 | 仅代理命中规则/额外本地规则 | 原基线关闭；额外规则若存在需核对优先级 |
| 插件设置→GEO数据库/大陆白名单订阅 | GeoSite、GeoIP、CN provider | 保持可用；TikTok、private、google、CN及Telegram分类依赖有效数据 |

四组与提供商均每60秒检测、5秒超时、期望204、lazy:false；不依赖面板打开。面板类型如实显示：首跳/默认为自动选择，良心云为故障回退，ISP为固定出口的select。不要点击固定自动组节点；原生手工固定可能影响自动返回。GLOBAL不定时检测。

良心云仅支持编号01–99及合同约定的类别/协议标签；任意改名不自动猜测。新编号加入无需手写完整节点名。两个订阅都必须是 `proxies` 列表的 Mihomo YAML。

## 分流与测试记录

按 REQUIREMENTS.md 逐项验证：四组归属、面板关闭后的新检测时间、最低延迟选择、良心云故障切换及恢复、TikTok完整链及播放、流媒体/普通网页/AI/GitHub下载、国内/局域网/手动直连及子域名。

## 停用并完整回退

1. 在覆写模块界面关闭本次 `dual-jp-cloud` 和 `dual-jp-local`。
2. 恢复备份中原可用的一套完整云模块及其配对本地模块、原排序、原配置匹配路径和原先选择。不要只关闭新云模块而留下新 `dialer-proxy` 引用的本地模块。
3. 全部恢复完成后统一重启一次 OpenClash，再确认普通代理、TikTok和直连恢复。没有额外控制器或监督进程需要停止，也无服务需要卸载。

若回退后仍失败，保存当前日志定位，不连续尝试其他版本。正式发布须先通过实机应用和完整回退，不覆盖原已发布快照。正式发布后继续使用原有滚动订阅地址。
