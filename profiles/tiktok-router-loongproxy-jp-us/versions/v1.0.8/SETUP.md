# tiktok-router-loongproxy-jp-us v1.0.8 — 候选设置与验收

状态：**candidate，未在本人路由器验证**。本文件不授权发布或切换生产配置。现有 v1.0.7 设置与完整操作说明见 [v1.0.7 SETUP.md](../v1.0.7/SETUP.md)。

## OpenClash 设置基线

沿用稳定版：Fake-IP 增强、规则代理模式，启用 UDP 转发、路由器本机代理和大陆 IPv4 绕过；关闭 IPv6 代理、IPv6 DNS 和附加 DNS；Dnsmasq 转发，DNS 遵守路由规则，Fake-IP 持久化。Fake-IP 过滤使用候选完整模块的规则模式。QUIC 等实际设备设置未因本候选改变，详见稳定版的具体条件和设置路径。

DNS 顺序仅在其他规则之前增加 `api.github.com` 的真实 IP 例外；TikTok、Google、私网、Manual-Direct 和中国域名现有顺序不变。真实 IP 不保证上游 DNS 一定可用或解析正确，仍需验证 TLS 与实际版本检查。

## 候选部署和验证

1. 在本人确认候选及回退方案后，通过 OpenClash **运行状态 → 覆写模块**，使用可核验的候选完整云覆写；同一配置只启用一个完整云模块及原有配套本地节点模块。保留原 v1.0.7 固定模块地址、模块顺序与设置；不修改本地节点或凭据。候选完整云模块必须通过远程订阅模块加载，不手工覆盖正式 v1.0.7 版本。
2. 路由器应用候选需重启 OpenClash，可能短暂中断网络。重启后核对插件和核心运行，并从 NEXUS API 容器只读确认 `api.github.com` 的 IPv4 不属于被 NEXUS 拒绝的地址范围。
3. 仅对本人创建的测试服务检查版本，查看 NEXUS 显示和微信消息；若 DNS 仍是 Fake-IP、版本检查失败或消息未到达，保留原始状态并停止，不连续重试。
4. 核对 GitHub 连接命中美国组，以及 TikTok 仍使用本人选定的 iKuuu 日本首跳和本地 ISP 节点；每项实际验证与静态检查分别记录。
5. 回退时停用候选并恢复原 v1.0.7 固定远程模块与既有顺序，重启 OpenClash；不删除本地节点模块或更改凭据。回退后重新核对原链路。

## 数据同步边界

当前候选以 v1.0.7 固定模块制作，**不包含其后 `main` 动态 Manual-Direct 源的更新**。在决定正式发布、同步滚动模块或长期使用前，须保留并重新合并当前 `rules/manual-direct.yaml` 的完整内容，再重新验证；不能用候选覆盖该源或历史发布快照。
